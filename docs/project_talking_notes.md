# 信贷风险项目笔记：两分钟说明版

> 目标：明天可以在两分钟内讲清项目大意；不要求背模型原理或补完技术细节。

## 两分钟版本 / 2-minute version

我做的是一个信贷风险评分、策略模拟和监控项目。它要解决的问题是：对一笔贷款，在已经看到借款人的信用和早期还款行为后，如何判断其未来一年内发生严重逾期的风险；再把这个风险判断变成通过、人工审核、拒绝的可执行规则，并持续检查客户结构或风险表现是否发生变化。

主数据来自 Fannie Mae 的美国单户住房贷款表现数据。我们没有把未来还款记录提前喂给模型：起源后第 1-6 个月的信息作为特征，第 7-18 个月内是否发生 90 天及以上逾期作为标签。这样构造出约 201.6 万条贷款快照。模型按时间切分，较早数据训练，2024-04-01 之后的数据完全留作时间外测试。

我保留逻辑回归作为透明基准，并用 XGBoost 捕捉非线性关系。在时间外测试集上，XGBoost 的 AUC 是 0.857、KS 是 0.540，高于逻辑回归的 0.841 和 0.522。但我不会只说模型“更好”：训练到时间外测试的 PSI 是 0.267，说明客群或分数分布发生了明显变化，上线前需要进一步复核稳定性。

最后，我将 PD 分数转成通过、人工审核、拒绝三档的策略模拟。例如平衡方案中，预测 PD 不高于 12% 的贷款通过，12%-30% 人工审核，高于 30% 拒绝。这样能比较不同风险偏好下的通过率、通过客群的实际坏样本率、预期损失和人工审核量。这个项目当前是基于历史数据的模拟，不宣称策略已在真实业务中上线。

---

## 1. 问题 / Problem

**要解决什么？**

给定一笔贷款的信用信息和早期还款行为，预测其未来 12 个月是否会发生严重逾期（90+ DPD），并将预测结果用于：

1. 风险排序：谁的未来违约风险更高？
2. 准入策略：低风险自动通过，中间风险进入人工审核，高风险拒绝。
3. 持续监控：后续新批次的客群、分数和坏样本率是否改变？

**一句话区分：**

- **模型分数（PD）** 回答“这笔贷款预计有多大风险”。
- **准入策略（policy）** 回答“机构面对这个风险，要采取什么动作”。

分数本身不是策略。策略是在分数上再加业务阈值、审核能力和风险偏好的决策规则。

## 2. 数据 / Data

**主案例（main case）：** Fannie Mae Single-Family Loan Performance Data，公开的美国单户住房贷款数据。

- 原始文件：`2021Q1.csv`、`2022Q1.csv`、`2023Q1.csv`、`2024Q1.csv`。
- 每行是“某笔贷款在某个月的一条表现记录”，同时保留起源时的静态信息，例如 FICO、LTV、DTI、原始贷款余额、用途、房产类型；也包含月度还款表现，例如当前余额、逾期状态、修改标识。
- 这四个文件是季度发布的数据文件，**不是**“前三年 Q1 训练、2024Q1 测试”这样简单的一一对应关系。
- 经过时点处理后得到 `2,015,703` 条可用贷款快照，整体 90+ DPD 坏样本率为 `0.61%`。

**时点定义（最关键的数据决策）：**

- 特征窗：贷款起源后第 1-6 个月。
- 结果窗：第 7-18 个月。
- 坏样本：结果窗内任意一个月出现 `90+ DPD`，即逾期状态大于等于 3。

这避免了数据泄露：模型在预测时不能提前知道未来还款情况。

**Baseline 是什么？**

`UCI Default of Credit Card Clients` 是项目早期用来快速检查数据质量和基础模型流程的小型基准案例。Fannie Mae 才是现在用于展示的**主案例**。两分钟介绍中不需要展开 UCI，也不需要说成有两套同等重要的数据。

更详细的“为什么四个 Q1 文件仍能形成 18 个月窗口”的说明见 [主数据源与实际文件结构](main_data_source.md)。

## 3. 方法 / Method

### 建模方式

当前主案例比较三类模型：

- **逻辑回归（logistic regression）**：可解释、透明的基准模型。
- **XGBoost**：能捕捉更复杂的非线性关系和变量交互；当前策略候选模型。
- **LightGBM**：第三个树提升挑战者，用相同 OOT 协议验证，作为 XGBoost 的独立对照。

注意：随机森林属于早期 UCI 基准案例，不是当前 Fannie Mae 主案例的运行模型。LightGBM 在 Python 3.10 隔离环境中已完成 OOT 比较；对外介绍时应说主项目有三个模型，而不是“四个模型”。完整决策见 [模型选择记录](model_selection_decision.md)。

### 时间外验证 / OOT validation

训练使用观察日期在 `2024-04-01` 之前的数据；该日及之后的 `131,334` 笔贷款完全留给测试。

这比随机切分更接近真实情境：真正使用模型时，面对的是之后才出现的贷款，而不是从同一时期随机抽出的记录。

### 冠军-挑战者 / Champion-challenger

这不是一个额外算法，而是一种模型治理方式：

- 逻辑回归是当前透明、易解释的**基准/Champion candidate**。
- XGBoost 是试图提升效果的**挑战者/Challenger**。
- 不是只看 AUC 最大就直接上线；还要看稳定性、校准、可解释性和运行风险。

本项目中 XGBoost 表现更高，但尚未正式宣称它是“最终线上冠军模型”。

## 4. 结果 / Results

### 模型效果

| 模型 | OOT AUC | OOT KS | 如何解释 |
| --- | ---: | ---: | --- |
| 逻辑回归 | 0.841 | 0.522 | 透明、可解释的基准 |
| XGBoost | 0.857 | 0.540 | 在时间外样本中风险排序更强 |
| LightGBM | 0.853 | 0.535 | 接近 XGBoost 的第三个挑战者，分数 PSI 更低 |

- **PD（Probability of Default）**：本项目中指“贷款在观察点之后未来 12 个月内发生 90+ DPD 的预测概率”。例如 PD 为 12%，表示模型预计同类条件下未来严重逾期风险约为 12%，不是已经违约。
- **AUC**：模型将坏样本排在好样本前面的能力，越接近 1 越好。
- **KS**：好坏样本分数分布能被拉开的最大距离，越高通常说明区分能力越强。

### 策略模拟

平衡方案的阈值是：

- `PD <= 12%`：通过（pass）。
- `12% < PD <= 30%`：人工审核（manual review）。
- `PD > 30%`：拒绝（reject）。

这套规则可以套到之后输入的、字段和口径一致的新贷款上；但阈值并不是“永远正确的公式”，需要随业务风险偏好、审核能力和新数据表现定期复核。

| 指标 | 它回答什么 | 平衡方案结果 |
| --- | --- | ---: |
| 通过率 | OOT 测试贷款中被直接通过的比例 | 99.50% |
| 审核率 | 需要投入人工审核的比例 | 0.21% |
| 通过客群坏样本率 | 在后来真实表现中，被通过贷款发生 90+ DPD 的比例 | 0.62% |
| 放款后预期损失 | 暂按“通过和人工审核最终放款”计算的预测风险金额 | 102.68M |
| 拒绝规避损失 | 被拒绝贷款对应的预测风险金额 | 30.30M |

**预期损失（Expected Loss, EL）** 不是实际亏损，计算为：

`PD × 暴露金额（本项目用原始贷款余额近似）× LGD`

其中 LGD 目前固定为 `40%` 的情景假设，不是从真实回收数据估出来的。因此这部分用于比较策略取舍，不能说成真实利润或真实回收损失。

### 漂移 / Drift

漂移指的是“今天进入模型的人群或分数分布，和模型训练时看到的人群不再相像”。例如新贷款的 FICO、LTV、早期逾期行为，或模型输出的 PD 分布发生改变。

- 训练集与 OOT 测试集的分数 PSI 是 `0.267`：按项目约定，高于 `0.25` 为明显漂移，需要复核。
- 2024Q2 与 2024Q3 的 PSI 是 `0.002`：后续两个 OOT 批次彼此稳定。

PSI 高不等于模型一定失效；它意味着不能只看过去的 AUC，需要检查客群结构、特征分布、数据质量和校准。

## 5. 我能解释的决策 / Decisions I Can Explain

以下是可以诚实说“我能解释为什么这样做”的部分：

1. 我没有随机切分数据，而是采用时间外测试，因为风险模型最终面对的是未来贷款。
2. 我用前 6 个月构造特征、后 12 个月构造标签，以避免把未来逾期信息泄露给模型。
3. 我保留逻辑回归，不只使用 XGBoost，因为风控需要性能，也需要可解释、稳定的基准。
4. 我没有把 PD 直接当成业务动作，而是用阈值转成通过、审核和拒绝，并比较其风险与运营取舍。
5. 我没有因为 XGBoost AUC 更高就声称可以上线；PSI 0.267 提醒我们还要检查漂移和校准。

**不应夸大的说法：**

- 不说“已经在真实业务上线”。
- 不说“12% 和 30% 是唯一最优阈值”。
- 不说“预期损失就是真实亏损”。
- 不说随机森林是当前 Fannie Mae 主案例的运行模型。
